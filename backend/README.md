# Сервер Ватсапки

Общая кодовая база для HTTP-сервера и фонового процесса. Требуется JDK 21;
Spring Boot зафиксирован на версии 3.5.16. Maven Wrapper 3.3.4 загружает
Maven 3.9.16 при первом запуске — отдельная установка Maven не нужна.
Компилятор использует `--release 21`.

Скрипты Maven Wrapper распространяются по Apache License 2.0; исходные
уведомления сохранены в `.mvn/wrapper/LICENSE` и `.mvn/wrapper/NOTICE`.

## Запуск

Команды выполняются из каталога `backend/`:

```sh
./mvnw spring-boot:run
```

По умолчанию включён профиль `backend`, сервер слушает `127.0.0.1:8080`.
Адрес и порт задаются переменными `SERVER_ADDRESS` и `SERVER_PORT`.
Для контейнера следует задать `SERVER_ADDRESS=0.0.0.0`.

Фоновый процесс запускается отдельно:

```sh
SPRING_PROFILES_ACTIVE=worker ./mvnw spring-boot:run
```

Выбирайте один профиль процесса: `backend` или `worker`. Worker не запускает
веб-сервер; `spring.main.keep-alive` удерживает процесс даже до регистрации
фоновых обработчиков. Оба профиля используют один набор классов и зависимостей.
На Windows используется `mvnw.cmd`, а переменная профиля задаётся средствами
текущей оболочки.

Корневой путь не обслуживает ресурс и возвращает общий JSON ошибки.
Для старта нужна доступная PostgreSQL: Hibernate только проверяет схему и не
создаёт таблицы.

## Контракт API

Контроллеры помечаются `@ApiV1Controller`: пути начинаются с `/api/v1`.
Даты сериализуются в UTC, ISO 8601; UUID передаётся строкой. Списки возвращают
`items`, `nextCursor` и `hasMore`, размер страницы не больше 50.

Ошибка приходит как `application/problem+json` с полями `status`, `code`,
`detail`, `fieldErrors` и `traceId`. Стек клиенту не отдаётся. Описание
контракта доступно на `/v3/api-docs`, страница — на `/swagger-ui.html`.
Защищённые операции используют схему `bearerAuth`; публичные помечаются
`@PublicApi`.

## База и Redis

Из корня репозитория:

```sh
cp .env.example .env
docker compose up -d postgres redis
docker compose run --rm migrate
```

`migrate` — отдельный одноразовый Flyway. Он подключается ролью
`whatsappka_migrate` и применяет SQL из `backend/src/main/resources/db/migration`.
Приложение подключается ролью `whatsappka_app` и схему не меняет. Пароль
администратора PostgreSQL приложению не передаётся.

Пул соединений API — 10, фонового процесса — 5. Redis ограничен 128 МиБ данных
внутри контейнера на 256 МиБ. `docker compose down` данные в volumes не удаляет.

MinIO собирается из зафиксированного исходного коммита, описание лежит в
`infra/minio`. Консоль не публикуется. Оба профиля читают `MINIO_ENDPOINT`:
на хосте это `http://127.0.0.1:9000`, в сети compose — `http://minio:9000`.
Приложение использует отдельный ключ, не корневой пароль хранилища.

```sh
docker compose build minio
docker compose up -d minio
docker compose run --rm minio-init
```

## Конфигурация

`.env.example` в этом каталоге задаёт адрес и роль приложения. Пароль миграций
живёт только в корневом `.env`. Spring Boot сам по себе не загружает файл
`.env`; переменные передаются оболочкой, IDE или средой развёртывания.

Клиенты Redis и MinIO в процесс пока не подключены: адрес и ключ уже читаются
из окружения. Реальные пароли и локальный `.env` не коммитятся.

## Пакеты

| Пакет | Область |
|---|---|
| `identity` | Учётные записи, роли и сессии |
| `profiles` | Профили пользователей |
| `social` | Подписки и личные блокировки |
| `content` | Посты, комментарии, реакции и лента |
| `communities` | Сообщества и членство |
| `messaging` | Чаты, сообщения и прочтение |
| `media` | Файлы и обработка изображений |
| `notifications` | Уведомления |
| `moderation` | Жалобы и санкции |
| `admin` | Управление платформой |
| `platform` | Общая инфраструктура и фоновые задания |

Изменение состояния другой области проходит через её прикладной интерфейс.
Разделение пакетами не создаёт самостоятельных микросервисов.
